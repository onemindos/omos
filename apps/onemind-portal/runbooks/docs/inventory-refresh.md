# Inventory refresh and retirement review

The six-hour discovery workflow proposes changes through one reusable pull request. It does not deploy, mutate provider resources or directly write to the catalog API. Enable `ONEMIND_INVENTORY_REFRESH_ENABLED=true` and `ONEMIND_INVENTORY_ORG_VISIBILITY_VERIFIED=true` only after configuring a dedicated self-hosted runner labeled `onemind-inventory-readonly` with read-only discovery access and verifying the credential sees every intended repository. GitHub Actions must permit workflow-created pull requests.

The runner requires Node 22, kubectl context `do-nyc3-omos-cloud`, Tailscale status access and GitHub repository metadata access. Set repository secret `ONEMIND_INVENTORY_DISCOVERY_TOKEN` to an independently provisioned fine-grained read-only organization repository-metadata credential, or equivalent short-lived GitHub App token. Discovery uses that secret exclusively; the workflow token is reserved for proposal writes restricted to omos. Verify the intended private repository list against the credential before setting the visibility-confirmation variable. A narrow token can silently omit hidden repositories, so discovery success alone does not verify visibility. Do not install an organization-wide write token. Keep the workflow disabled until visibility is verified.

`refresh-inventory.cjs` requires successful Kubernetes, mesh and repository discovery plus curated Fabric reconciliation. On any source failure, all generated files are restored. Entity names remain unchanged. Missing resources retain their last observation, relationship targets and documentation. Three complete observations mark a retirement-review candidate; removal always requires human review. A missing result never proves resource deletion.

Review observed-at and last-checked-at annotations independently of live health. Fresh snapshots still depend on review/merge before production catalog updates. A failed scheduled run is visible in GitHub Actions; configure repository notifications for failures. Repository listings at the discovery limit fail closed instead of publishing truncated results.

Official references: [catalog integrations](https://backstage.io/docs/features/software-catalog/external-integrations/), [scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
