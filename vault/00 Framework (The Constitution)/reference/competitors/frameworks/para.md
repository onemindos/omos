## What It Does

PARA is a simple, universal system for organizing digital information. It uses just four top-level folders to organize everything by how actionable it is, making it easy to find things and keep active work separate from reference material.

---

## The Four Folders

```
PROJECTS     → Short-term efforts with deadlines and goals
AREAS        → Ongoing responsibilities (no end date)
RESOURCES    → Topics of interest for future reference
ARCHIVES     → Inactive items from the above three
```

### Projects

**Definition:** A series of tasks linked to a goal, with a deadline.

Examples:

- Complete website redesign (deadline: March 1)
- Plan vacation to Japan
- Write quarterly report
- Launch new product feature

**Key trait:** Projects END. They have a finish line.

### Areas

**Definition:** Spheres of activity with a standard to maintain over time.

Examples:

- Health
- Finances
- Career
- Home
- Relationships
- Professional development

**Key trait:** Areas are ONGOING. No end date, just standards to maintain.

### Resources

**Definition:** Topics or themes of ongoing interest.

Examples:

- Photography techniques
- Productivity methods
- Industry research
- Recipes
- Travel destinations

**Key trait:** Not tied to a project or area — pure interest/reference.

### Archives

**Definition:** Inactive items from the other three categories.

Contains:

- Completed projects
- Areas no longer active
- Resources no longer relevant

**Key trait:** Out of sight but retrievable. Nothing is deleted.

## Core Concepts

| Concept                        | Description                                                              |
| ------------------------------ | ------------------------------------------------------------------------ |
| **Actionability Spectrum**     | Organize by how actionable (Projects > Areas > Resources)                |
| **Progressive Summarization**  | Layer 1: Capture → Layer 2: Bold → Layer 3: Highlight → Layer 4: Summary |
| **CODE Method**                | Capture → Organize → Distill → Express                                   |
| **Just-In-Time Organization**  | Organize only when needed, not preemptively                              |
| **Cross-Platform Consistency** | Same PARA structure across all apps/devices                              |
| **Information Lifecycle**      | Move items between folders as status changes                             |

## The CODE Method

PARA is part of the larger Building a Second Brain system:

```
C - CAPTURE    → Save only what resonates
O - ORGANIZE   → Use PARA to file information
D - DISTILL    → Progressive Summarization
E - EXPRESS    → Create outputs from your notes
```

---

## Progressive Summarization

The killer technique for making notes useful:

| Layer       | What You Do                       | When                    |
| ----------- | --------------------------------- | ----------------------- |
| **Layer 1** | Capture the original content      | Import time             |
| **Layer 2** | Bold the most important passages  | First review            |
| **Layer 3** | Highlight key phrases within bold | Deeper review           |
| **Layer 4** | Write executive summary at top    | When you really need it |

**Philosophy:** Don't over-process upfront. Let notes "earn" more attention over time.

## Strengths ✅

- **Extremely simple** — only 4 folders to learn
- **Low friction adoption** — can implement in an afternoon
- **Universal structure** — works in any app (Notion, Obsidian, Google Drive, Dropbox)
- **Actionability focus** — keeps active work separate from reference
- **Flexible** — adapts to personal needs without rigid rules
- **Progressive Summarization** — efficient knowledge distillation technique
- **Well-documented** — extensive courses, books, and community support
- **Project-centric** — aligns well with modern project-based work
- **No maintenance overhead** — minimal ongoing organization effort

---

## Weaknesses ❌

- **No task management** — pairs with GTD but doesn't replace it
- **No AI integration** — static file storage only
- **Weak on emergence** — not designed for idea synthesis/linking
- **No automation** — manual maintenance only
- **Areas can bloat** — ongoing responsibilities pile up without review
- **Resources become graveyards** — easy to collect, hard to resurface
- **No metrics** — no built-in tracking of knowledge growth or usage
- **Individual-centric** — not designed for shared knowledge bases
- **Folder-based thinking** — misses benefits of linked notes

## Relationship to OneMind

**PARA influences OneMind structure:**

- Projects → Active work in each domain
- Areas → The four domains (HP, LE, GE, UI)
- Resources → Reference materials within domains
- Archives → Archived items

**Key differences:**

1. OneMind uses numbered folders (Johnny Decimal) vs. named folders
2. OneMind adds AI agents, automation, and metrics
3. OneMind is life-scope (not just information)
4. OneMind includes task management

**Hybrid approach:** PARA-style organization can work within OneMind's numbered structure.
