## Getting Things Done (GTD)

**Created by:** David Allen (2001)
**Book:** *Getting Things Done: The Art of Stress-Free Productivity*

### The Five-Step Framework

```
1. CAPTURE     → Get everything out of your head
2. CLARIFY     → Process what each item means
3. ORGANIZE    → Put items where they belong
4. REFLECT     → Review your system regularly
5. ENGAGE      → Take action with confidence
```

### Core Concepts

| Concept | Description |
|---------|-------------|
| **Inbox Zero** | Process all inputs to empty inbox |
| **Next Actions** | Define the very next physical action |
| **Contexts** | Group tasks by location/tool (@home, @computer, @calls) |
| **Projects** | Any outcome requiring more than one action |
| **Weekly Review** | Regular reflection to keep system current |
| **Someday/Maybe** | Holding pen for ideas not ready for action |
| **Waiting For** | Tracking delegated items |
| **Reference** | Storage for non-actionable information |

### Strengths ✅

- **Battle-tested for 20+ years** — millions of practitioners worldwide
- **Reduces cognitive load** — "mind like water" through externalization
- **Universal applicability** — works for any profession or lifestyle
- **Clear action orientation** — always know your next step
- **Stress reduction** — captured items don't weigh on memory
- **Context-switching efficiency** — batch similar tasks together
- **Tool-agnostic** — paper, apps, or hybrid systems all work

### Weaknesses ❌

- **No knowledge management** — weak on learning and idea synthesis
- **No AI integration** — designed for humans working alone
- **High maintenance** — Weekly Review requires discipline
- **Can become bureaucratic** — rigid adherence adds overhead
- **No metrics or tracking** — success is qualitative, not measured
- **Individual focus** — not designed for teams or family coordination
- **Information storage is flat** — Reference folder becomes a dumping ground
- **Dated contexts** — @phone, @office less relevant in mobile/remote era

### Best For

- Professionals with heavy task loads
- People feeling overwhelmed by commitments
- Those seeking stress reduction and mental clarity
- Knowledge workers with many projects

## PARA Method

**Created by:** Tiago Forte (2017)
**System:** *Building a Second Brain* (BASB)

### The Four Folders

```
PROJECTS     → Short-term efforts with deadlines
AREAS        → Ongoing responsibilities (no end date)
RESOURCES    → Topics of interest for future reference
ARCHIVES     → Inactive items from the above three
```

### Core Concepts

| Concept | Description |
|---------|-------------|
| **Actionability Spectrum** | Organize by how actionable (Projects > Areas > Resources) |
| **Progressive Summarization** | Layer highlights to distill key insights |
| **CODE Method** | Capture → Organize → Distill → Express |
| **Information Lifecycle** | Move items between folders as status changes |
| **Cross-platform** | Same structure across all apps/devices |

### Strengths ✅

- **Extremely simple** — only 4 folders to learn
- **Low friction adoption** — can implement in an afternoon
- **Universal structure** — works in any app (Notion, Obsidian, Google Drive)
- **Actionability focus** — keeps active work separate from reference
- **Flexible** — adapts to personal needs without rigid rules
- **Progressive Summarization** — efficient knowledge distillation technique
- **Well-documented** — extensive courses, books, and community support
- **Project-centric** — aligns well with modern project-based work

### Weaknesses ❌

- **No task management** — pairs with GTD but doesn't replace it
- **No AI integration** — static file storage only
- **Weak on emergence** — not designed for idea synthesis/linking
- **No automation** — manual maintenance only
- **Areas can bloat** — ongoing responsibilities pile up without review
- **Resources become graveyards** — easy to collect, hard to resurface
- **No metrics** — no built-in tracking of knowledge growth or usage
- **Individual-centric** — not designed for shared knowledge bases

### Best For

- Digital pack rats drowning in files
- Those who collect but can't find things
- People wanting a simple, quick-start system
- Knowledge workers who need organized reference material

## Zettelkasten Method

**Created by:** Niklas Luhmann (1950s-1990s)
**Result:** 70 books, 400+ academic papers using 90,000+ notes

### The Three Note Types

```
FLEETING NOTES    → Quick captures, temporary
LITERATURE NOTES  → Annotations on source material
PERMANENT NOTES   → Atomic, evergreen ideas in your own words
```

### Core Concepts

| Concept | Description |
|---------|-------------|
| **Atomic Notes** | One idea per note, complete in itself |
| **Linking** | Notes connect to related notes via explicit links |
| **Unique Identifiers** | Each note has a permanent address |
| **Emergence** | New ideas arise from connection patterns |
| **Writing as Thinking** | Notes force you to process and articulate |
| **Hub Notes** | Index notes that map topic clusters |
| **Bottom-Up Structure** | Organization emerges, not imposed |

### The Process

1. **Capture** → Take fleeting notes on ideas/readings
2. **Annotate** → Create literature notes with your commentary
3. **Synthesize** → Write permanent notes in your own words
4. **Connect** → Link new notes to existing notes
5. **Review** → Traverse links to spark new connections

### Strengths ✅

- **Exceptional for writing** — proven to produce massive output (Luhmann's 70 books)
- **Idea synthesis** — connections generate new insights automatically
- **Long-term value** — notes compound over years and decades
- **Forces understanding** — rewriting in your own words deepens learning
- **Scales infinitely** — Luhmann managed 90,000 notes effectively
- **Retrieval through links** — find ideas via association, not search
- **Academic-grade** — best for research, writing, and scholarship
- **Evergreen system** — notes remain relevant indefinitely

### Weaknesses ❌

- **High learning curve** — takes months to internalize the method
- **Slow to start** — significant upfront investment before payoff
- **No task management** — purely knowledge-focused
- **No AI integration** — designed for human-only workflows
- **Requires discipline** — daily practice needed to maintain momentum
- **Not for action items** — poor fit for task-oriented people
- **Linking overhead** — each note requires intentional connection work
- **Tool-dependent** — needs software with bidirectional linking
- **Individual-focused** — not designed for team collaboration

### Best For

- Researchers and academics
- Writers and content creators
- People with long-time-horizon knowledge goals
- Those who prioritize depth over breadth

## OneMind Codex

**Created by:** Zeus Delacruz (2025)
**Philosophy:** Solar-punk, generational thinking, human + AI unity

### The Structure

```
00-24  UI  → Sovereign Operations (The Brain / Coordination)
25-49  HP  → Holistic Performance (Self / Personal Growth)
50-74  LE  → Legacy Evolution (Family / Generational)
75-99  GE  → Generational Empire (Business / Wealth)
```

### Core Concepts

| Concept | Description |
|---------|-------------|
| **Human + AI = One Mind** | AI agents as active partners, not passive tools |
| **Three Paths + Brain** | Life organized into Self, Family, Business + Coordination layer |
| **Intelligence Scores** | PI (Performance), LI (Legacy), WI (Wealth), Unified Score |
| **Numbered Folders (00-99)** | Johnny Decimal-inspired navigation |
| **Agent Autonomy Levels** | Observer → Advisor → Executor → Guardian |
| **Generational Design** | Built for 50+ year sustainability and family transfer |
| **Solar-Punk Values** | Technology serves human flourishing, not just productivity |

### The Layer Model

1. **Identity & Principles** — Why you exist (values, mission, vision)
2. **Life Domains** — What life is made of (HP, LE, GE, UI)
3. **Entities** — What you work with (projects, tasks, knowledge, agents)
4. **Flows** — How things move (capture → process → execute → measure)
5. **Interfaces** — Where you interact (apps, voice, chat, robots)
6. **Agents** — Who does the work (human, AI, hybrid)

### Strengths ✅

- **AI-native design** — built for human + AI collaboration from day one
- **Life-scope coverage** — personal, family, AND business unified
- **Generational thinking** — 50+ year horizon, not just quarterly goals
- **Metrics-driven** — Intelligence Scores track actual progress
- **Automation-ready** — n8n, agents, IoT integration baked in
- **Philosophy-grounded** — solar-punk values beyond pure productivity
- **Flexible structure** — numbered folders scale from simple to complex
- **Memory persistence** — AI agents maintain context across sessions
- **Physical world integration** — robotics, home automation, IoT

### Weaknesses ❌

- **Newest system** — unproven at scale, limited community
- **High complexity** — steeper learning curve than PARA or GTD
- **Infrastructure overhead** — requires tech stack (Obsidian, Letta, n8n, etc.)
- **Creator-specific** — built for one person's life, may not generalize
- **AI dependency** — full value requires AI agent setup and maintenance
- **Documentation-heavy** — lots of doctrine to absorb before starting
- **Niche philosophy** — solar-punk/generational focus not for everyone
- **Unproven longevity** — less than 1 year old vs. GTD's 20+ years
- **Technical requirements** — needs comfort with APIs, automation, code

### Best For

- Tech-savvy individuals wanting AI integration
- People thinking in generational/legacy terms
- Those seeking unified human enhancement framework (not just tasks OR knowledge)
- Makers comfortable building custom systems

## Which Framework Should You Choose?

### Choose GTD if you...
- Feel overwhelmed by tasks and commitments
- Want proven, battle-tested methodology
- Need immediate stress relief
- Prefer simplicity over complexity
- Don't need AI or automation

### Choose PARA if you...
- Drown in digital files and folders
- Want the simplest possible system
- Need cross-platform consistency
- Collect information but can't find it later
- Want to start today, not next month

### Choose Zettelkasten if you...
- Write books, papers, or long-form content
- Think in long time horizons (decades)
- Value depth of understanding
- Have patience for slow compound returns
- Enjoy the process of knowledge building

### Choose OneMind Codex if you...
- Want AI agents as active life partners
- Think in generational/legacy terms
- Are comfortable with technical complexity
- Want tasks + knowledge + automation unified
- Align with solar-punk philosophy
- Accept risk of using a new, unproven system

### Hybrid Approaches

Most effective practitioners combine systems:

| Combination | What You Get |
|-------------|--------------|
| **GTD + PARA** | Task clarity + file organization |
| **GTD + Zettelkasten** | Action efficiency + knowledge depth |
| **PARA + Zettelkasten** | File organization + idea synthesis |
| **OneMind + GTD core** | AI integration + proven task methodology |
| **OneMind + Zettelkasten linking** | Enhancement Framework + deep knowledge building |

## Conclusion

There is no "best" productivity framework — only the best fit for your:

1. **Goals** — Tasks? Knowledge? Life integration?
2. **Timeline** — Quick start or long-term investment?
3. **Technical comfort** — Paper to high-tech?
4. **Philosophy** — Efficiency vs. emergence vs. legacy?

**Proven and Safe:** GTD + PARA
**Deep Knowledge Work:** Zettelkasten
**Ambitious AI Integration:** OneMind Codex

The most honest recommendation: **start simple (GTD or PARA), add depth (Zettelkasten) as needed, and evaluate OneMind Codex as it matures and proves itself in the real world.**
