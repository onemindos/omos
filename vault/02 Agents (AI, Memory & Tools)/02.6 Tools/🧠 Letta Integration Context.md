**How Letta Works (Critical Context)**

- **Stateful memory**: Never forgets, updates memory blocks over time
- **Tool calling**: Can execute functions via MCP protocol
- **Self-editing memory**: Agent updates its own memory based on conversations
- **Persistent agents**: Each agent has personality, context, ongoing memory

**Letta + Obsidian = Powerful**

1. **Semantic search**: Letta can search your entire vault for relevant context
2. **Architecture awareness**: Agents understand system design from docs
3. **Decision context**: Agents reference your decision logs and principles
4. **Learning**: Agents update their memory based on what they read in vault
5. **Operational intelligence**: Agents can troubleshoot using runbooks in vault

**Key Letta Concepts to Remember**

- **Core Memory**: Always-loaded context (personality, user info, preferences)
- **Archival Memory**: Long-term storage, searched when needed
- **Recall Memory**: Recent conversation history (sliding window)
- **Tools**: Functions agents can call (MCP protocol)
- **Blocks**: Editable memory sections agents can modify

**Why This Architecture Works**

- Letta agents have **persistent access** to unified knowledge base
- No context switching between tools
- Single source of truth for both human and AI
- Agents can reference architecture, operations, and research docs in real-time
- Your brain (Obsidian) = Letta's brain (memory system)
