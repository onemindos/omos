## 5. Email Architecture

> **Simplified 2026-03-21.** Unified inbox with tags. No pillar aliases. The `@zeusdelacruz.me` domain must stay live through the migration window — needed to receive confirmation emails when updating 100+ accounts. Drop it after migration is done.

### Design Principles

1. **One inbox, tags for context** — everything lands in one place, tags provide filtering
2. **No pillar aliases** — `ui@/hp@/le@/ge@` adds complexity with no payoff for a solo operator
3. **Sender-based filters** — auto-tag by who sent the email (Stripe → `business`, GitHub → `tech`, etc.)
4. **Stay on Zoho** — AI agents need IMAP/API access (Proton blocks this)

### Task Architecture

```
TODOIST (Zeus's Hub)          ZOHO (Business Ops)
├── Personal projects          ├── CRM deal actions
├── Daily/weekly planning      ├── Support tickets
├── AI-assigned tasks          └── Desk tickets
└── Family/life tasks
            │
            └────────┬────────┘
                     │
                     ▼
            ┌──────────────────┐
            │   LEGACY AI      │
            │   (Letta)        │
            └────────┬─────────┘
                     │
     ┌───────────────┼───────────────┐
     ▼               ▼               ▼
┌──────────┐   ┌──────────┐   ┌──────────┐
│ Todoist  │   │   Zoho   │   │   Home   │
│Python API│   │Python API│   │Assistant │
└──────────┘   └──────────┘   └──────────┘
```

**Tool Access Method:**
- **Todoist:** Python tools via API (Legacy uses labels like `@Legacy` for filtering)
- **Zoho:** Python tools via API (not MCP - Letta uses Python tools, not MCP protocol)
- **Home Assistant:** REST API + existing integration
- **GitHub:** Legacy added as collaborator (notifications → command@legacyhq.ai)

**Why Not Add Legacy as User in Todoist/Zoho:**
- She operates via API, not UI
- Labels/filters work for task assignment
- Adding users = extra cost with no functional benefit
- Her email (command@legacyhq.ai) serves as notification aggregator
