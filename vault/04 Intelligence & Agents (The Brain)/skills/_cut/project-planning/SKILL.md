# Project Planning Skill

You help break down projects into clear, actionable plans with realistic timelines.

## When to Use

- User has a new project or goal
- Large task needs breaking down
- User asks "How should I approach X?"
- Roadmap or timeline needed

## Planning Process

### 1. Define Success
- What does "done" look like?
- What are the must-haves vs nice-to-haves?
- Any constraints (time, budget, resources)?

### 2. Identify Major Phases
- Break into 3-7 major milestones
- Each milestone = deliverable outcome
- Natural checkpoints for review

### 3. Break Down Tasks
- Each phase → specific tasks
- Tasks should be < 4 hours
- Clear definition of done per task

### 4. Identify Dependencies
- What blocks what?
- What can be parallelized?
- What's on the critical path?

### 5. Estimate & Schedule
- Time estimate per task
- Add buffer (usually +30-50%)
- Map to calendar if needed

## Project Breakdown Template

```
## Project: [Name]

### Goal
[One sentence: What are we trying to achieve?]

### Success Criteria
- [ ] [Measurable outcome 1]
- [ ] [Measurable outcome 2]
- [ ] [Measurable outcome 3]

### Constraints
- Timeline: [Date/Duration]
- Resources: [What's available]
- Budget: [If applicable]

---

### Phase 1: [Name] (Est: X days)
**Milestone:** [Deliverable]

Tasks:
- [ ] Task 1 (Est: 2h)
- [ ] Task 2 (Est: 4h)
- [ ] Task 3 (Est: 1h)

### Phase 2: [Name] (Est: X days)
**Milestone:** [Deliverable]

Tasks:
- [ ] Task 1 - depends on Phase 1
- [ ] Task 2
- [ ] Task 3

### Phase 3: [Name] (Est: X days)
**Milestone:** [Deliverable]

Tasks:
- [ ] Task 1
- [ ] Task 2
- [ ] Task 3

---

### Timeline Overview
| Phase | Start | End | Status |
|-------|-------|-----|--------|
| Phase 1 | [Date] | [Date] | Not Started |
| Phase 2 | [Date] | [Date] | Not Started |
| Phase 3 | [Date] | [Date] | Not Started |

### Risks
- [Risk 1]: [Mitigation]
- [Risk 2]: [Mitigation]

### Next Actions
1. [First thing to do right now]
2. [Second thing]
```

## Estimation Tips

- Break down until tasks are < 4 hours
- Use relative sizing (S/M/L) first, then hours
- Track actuals to improve future estimates
- Always add buffer for unknowns

## Anti-Patterns to Avoid

- Planning too far ahead in detail
- No clear "done" criteria
- Ignoring dependencies
- No buffer time
- Not reviewing/adjusting the plan
