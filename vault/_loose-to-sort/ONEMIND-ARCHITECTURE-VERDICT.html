THE ORGANIZING PRINCIPLE — one pattern answers everything.
Every big system you have — ORP, Constellation, AMOS, TAK Server — was built as a full platform: each ships its own bus, its own video/RTSP, its own federation, its own comms, its own entity model. But OneMind already owns those layers: NATS is the bus, TAK Server 5.7 is comms/video/chat/data-sync, MediaMTX is RTSP ingest, WorldWideView is the map. So the overlaps aren't accidents — they're four platforms competing for the same jobs.

The rule: from each system take its ONE unique brain, wire it to our existing spine, and disable its redundant platform features. Keep the brain, drop the duplicate plumbing.

What supercharges · what doesn't

SUPERCHARGERS — invest here

  • Generalize ORP to publish ALL entity types (not just air) → every domain flows to ATAK + WWV in one move. Highest leverage in the whole system.
  • AMOS mission layer → the proactive multi-asset ops OneMind completely lacks today.
  • WorldWideView + Agent Bus → Legacy flies the globe, toggles layers, runs queries.
  • K8s cloud hub → always-on brains independent of the Mac being awake.
  • Cherry-pick upstream ORP v0.4 adapters into the fork as needed.

NOT superchargers — don't over-invest

  • Running upstream ORP alongside the fork (redundant data plane).
  • Standing up Constellation as a live system (reference only — value already extracted).
  • Deploying WorldMonitor/Osiris as parallel frontends (they're feed sources).
  • Building video/chat/federation/data-sync (TAK Server already ships them).
  • Adopting AMOS's parallel TAK/MAVLink/comms layer (we have those on NATS).
  • Two entity ontologies (ORP + Constellation) — pick ORP.

Which way, given K8s?

Cloud-hub-first for brains, NEX-edge for hardware only.
The always-on brains — ORP fusion, om-overwatch kill-chain, AMOS, Legacy, Hermes, TAK Server, WorldWideView, observability — become DOKS containers (independent of the Mac). The only things that stay NEX on the Mac/edge sites are hardware-tethered: MAVLink bridge, Home Assistant bridge, local vision, MediaMTX. NATS is the spine under both. This is your four-plane doctrine, now concrete: containerize the recovered workloads → deploy to DOKS → keep the edge thin.
