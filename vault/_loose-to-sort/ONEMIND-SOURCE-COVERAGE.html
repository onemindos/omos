OneMind — Full Source & Sensor Coverage Map

Every source across ORP (40 protocol adapters), Crucix (29 OSINT feeds), WorldMonitor (568 feeds + ~24 geo-intel layers), and Osiris (cyber-OSINT + CCTV) — mapped by intelligence domain, with the real gaps called out.

Generated 2026-07-06 by Legacy · enumerated directly from each repo's source files

The core insight — there are 3 tiers of "source," not one. ORP owns the protocol tier (how raw sensor data arrives). Crucix / WorldMonitor / Osiris own the curated-feed and news/visual tiers (named intelligence over HTTP). ORP's universal adapters (generic_api, http_poller, websocket_client) are the mechanism to pull tiers 2 & 3 onto the bus — the pre-built integration logic in Crucix/WM/Osiris are the recipes to port into NATS publishers. The pie is ~90% complete; the work is unifying it onto NATS→ORP, not hunting new sources.

Tier 3 — News / Visual

568 + CCTV

WM 568 world-news feeds + Osiris CCTV/webcams. Narrative & visual context: global RSS in ~15 languages, EarthCam/RTSP/HLS/MJPEG public cameras.

The real gaps — the only new work

1 · ROS 2 / DDS connector — the robotics gap. Turns ORP from "sees drones" to "fuses robots." Highest priority new adapter.
2 · Seismic/disaster connector — USGS + GDACS + EONET only live in WorldMonitor's JS today. Add as an ORP adapter (or NATS publisher) so quakes/tsunamis/volcanoes hit the entity graph.
3 · RF / SIGINT — only kiwisdr. Thin. Optional expansion (SDR spectrum, more RF decode).
4 · Financial feeds → NATS — Crucix's 8 economic sources are pure JS today. Port to NATS publishers so the economic domain is on the bus, not siloed in Crucix.

How it converges

Every Crucix source file, every WM data layer, every Osiris feed becomes a NATS publisher → ORP ingests via generic_api/http_poller → entity graph + intel.* streams → WorldWideView renders it, ATAK gets the tactical slice, Legacy queries it with ORP-QL. Crucix/WM/Osiris aren't apps to deploy — they're recipe libraries to port, one source at a time, then archive. Same process-of-elimination as the repo sweep.
