## The Three Flows

### Flow 1: Knowledge Flow (PKM)

```
   CAPTURE          DISTILL          CONNECT          CODIFY
      │                │                │                │
      ▼                ▼                ▼                ▼
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Inbox   │ →  │  Draft   │ →  │  Linked  │ →  │  Canon   │
│  Notes   │    │  Notes   │    │  Notes   │    │  (Codex) │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     ↑                                                │
     │                                                │
     └────────────── FEEDBACK LOOP ───────────────────┘
```

**Stages:**
1. **Capture**: Raw inputs into Inbox (ideas, links, voice memos)
2. **Distill**: Process into atomic Knowledge Nodes
3. **Connect**: Link to Areas, Projects, other nodes
4. **Codify**: Mature knowledge becomes canonical (Legacy Codex pages)

### Flow 2: Action Flow (Execution)

```
   INTAKE          DESIGN          DECOMPOSE         EXECUTE         REVIEW
      │               │                │                │               │
      ▼               ▼                ▼                ▼               ▼
┌──────────┐   ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Intent  │ → │ Workflow │ →  │  Tasks   │ →  │  Action  │ →  │  Metric  │
│  (Goal)  │   │  Design  │    │  (Atomic)│    │ Execution│    │  Review  │
└──────────┘   └──────────┘    └──────────┘    └──────────┘    └──────────┘
                    ↑                                               │
                    │                                               │
                    └───────── UPDATE WORKFLOWS ────────────────────┘
```

**Stages:**
1. **Intake**: New intent enters (project goal, request)
2. **Design**: Human + AI design the workflow
3. **Decompose**: Workflow generates atomic tasks
4. **Execute**: Agents (human/AI/robot) complete actions
5. **Review**: Measure results, update workflows

## Appendix D: The Three-Question Routing Test

When content spans multiple pillars, use this test:

1. **What is the PRIMARY PURPOSE?**
   - Make money → GE
   - Improve self → HP
   - Protect family/future → LE
   - Automate/amplify → IT

2. **Who is the PRIMARY BENEFICIARY?**
   - Business → GE
   - Individual → HP
   - Family → LE
   - Systems → IT

3. **What is the TIMEFRAME?**
   - Revenue-focused → GE
   - Current growth → HP
   - Generational → LE
   - Infrastructure → IT

**Result:** Primary pillar = where the PROJECT lives. Tag secondary pillars.

## Appendix E: Security Principles

One Mind operates on a security-first foundation:

| Principle | Implementation |
|-----------|----------------|
| **Private Repository** | Not publicly accessible; invitation only |
| **No Secrets in Repo** | Use `.env` files locally, GitHub Secrets for CI/CD |
| **SSH Key Auth** | All VM deployments use SSH keys, never passwords |
| **Zero-Trust Access** | Cloudflare Tunnel for all self-hosted services |
| **Human-in-the-Loop** | Critical decisions (L3+) require explicit approval |
| **Encryption at Rest** | Sensitive data encrypted in vault and backups |
| **Audit Trail** | Git history + agent logs preserve all changes |

### Security Guardrails for AI Agents

- **Never** commit credentials, API keys, or secrets
- **Never** execute destructive commands without HITL approval
- **Never** access external services not in the approved list
- **Always** log actions that modify state
- **Always** verify before irreversible operations
