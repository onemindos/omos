# omos-ha Tailscale Add-on Crash — Fix Runbook

## Symptom

- `omos-ha` disappears from `tailscale status` or shows offline
- `tailscale ping 100.64.25.12` times out
- HA device still reachable on LAN at `192.168.1.180`
- Container logs show: `FATAL: Unable to start up Tailscale`
- Specific error: `Error: changing settings via 'tailscale up' requires mentioning all non-default flags`

## Root Cause

**`RunSSH: true` is saved in `tailscaled.state` but the add-on schema (v0.28.1) does not include `ssh` as a configurable option.**

The `tailscaled.state` file retains `RunSSH: true` from a prior manual `tailscale set --ssh` command. On startup, the add-on calls `tailscale up` without `--ssh`. Tailscale detects the mismatch between the saved state and the startup flags, refuses to run, and the container exits with code 1.

Key facts:
- `options.json` is regenerated by the Supervisor on every start — writing to it directly is overridden
- `ssh` was removed from the add-on's config schema in v0.28.1 — you can't set it via HA UI
- The fix must patch `tailscaled.state` directly

State file location (host path, accessed via Docker):
```
/mnt/data/supervisor/addons/data/a0d7b954_tailscale/tailscaled.state
```

The state is a JSON file where the active profile (`profile-f4f0`) is base64-encoded. The `RunSSH` key inside the decoded profile controls this behaviour.

## Fix

**Requires**: LAN access to `192.168.1.180` (SSH).

```bash
# Step 1 — SSH to omos-ha via LAN
ssh hassio@192.168.1.180

# Step 2 — Stop the add-on if running
sudo docker stop addon_a0d7b954_tailscale

# Step 3 — Patch RunSSH=false in tailscaled.state via Python Alpine container
sudo docker run --rm \
  -v /mnt/data/supervisor/addons/data/a0d7b954_tailscale:/tsdata \
  python:3-alpine python3 -c "
import json, base64

with open('/tsdata/tailscaled.state') as f:
    d = json.load(f)

raw = d.get('profile-f4f0', '')
decoded = base64.b64decode(raw + '==').decode()
prefs = json.loads(decoded)

print('Before - RunSSH:', prefs.get('RunSSH'), '| WantRunning:', prefs.get('WantRunning'))
prefs['RunSSH'] = False
prefs['WantRunning'] = True
print('After  - RunSSH:', prefs.get('RunSSH'), '| WantRunning:', prefs.get('WantRunning'))

encoded = base64.b64encode(json.dumps(prefs, separators=(',',':')).encode()).decode().rstrip('=')
d['profile-f4f0'] = encoded

with open('/tsdata/tailscaled.state', 'w') as f:
    json.dump(d, f, indent=2)
print('Written.')
"

# Step 4 — Start the add-on
sudo docker start addon_a0d7b954_tailscale

# Step 5 — Verify from Mac (wait ~20s)
tailscale status | grep omos-ha
```

Expected: `100.64.25.12  omos-ha  Zeus-Delacruz@  linux  -`

## Why Python Alpine Container?

The `hassio` SSH user can't write to the add-on data directory directly even with sudo. Using `docker run` with a bind mount sidesteps the permission restriction. Alpine alone lacks Python — use `python:3-alpine`.

## Why Not Write options.json?

The HA Supervisor regenerates `options.json` from its own internal database every time the container starts. Any direct write to `options.json` is overwritten before Tailscale reads it.

## Prevention

**Never run `tailscale set --ssh` or `docker exec ... tailscale set --ssh` manually on HA OS.** Doing so writes `RunSSH: true` into `tailscaled.state`. Since `ssh` is not in the v0.28.1 add-on schema, there is no way to clear it via the HA UI — it can only be fixed by patching the state file as above.

If Tailscale SSH on HA is needed in future, check the add-on changelog for a version that re-adds `ssh` to its schema.
