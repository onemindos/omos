# OneMind-Codex: Overview & Philosophy

## What is OneMind-Codex?

The OneMind-Codex is a **cognitive operating system** - a sophisticated, hierarchical knowledge management system that organizes an entire life into four interconnected pillars. It's not just note-taking; it's a complete framework for human-AI partnership designed for generational transfer (50+ years).

## Core Architecture

```yaml
ONE MIND SYSTEM
     │
     ├─── UI (00-24): Sovereign Operations - The Brain
     │    └─── Coordinates: Agents, Frameworks, Tech Stack, Automation
     │
     ├─── HP (25-49): Holistic Performance - Self Path
     │    └─── Question: "Does this improve ME?"
     │    └─── Score: PI (Performance Intelligence)
     │
     ├─── LE (50-74): Legacy Evolution - Family Path
     │    └─── Question: "Does this protect US?"
     │    └─── Score: LI (Legacy Intelligence)
     │
     └─── GE (75-99): Generational Empire - Business Path
          └─── Question: "Does this create VALUE?"
          └─── Score: WI (Wealth Intelligence)
```

**Unified Score = (PI + LI + WI) / 3** (Weekly health check)

## The 10 Principles of One Mind

1. **One Human, One Mind** - All systems plug into a single cognitive layer
2. **Solar-Punk First** - Technology serves flourishing, not just productivity
3. **AI as Companion** - Agents assist within human-defined guardrails
4. **Knowledge → Intelligence → Action** - Complete information loop
5. **Metrics Drive Truth** - What gets measured gets managed
6. **Systems Over Goals** - Repeatable workflows beat willpower
7. **Tool-Agnostic Architecture** - Framework independent of tools
8. **Generational Sustainability** - Built for 50+ year transfer
9. **Teach As You Build** - Wins become lessons
10. **Bridge Solar and Cyber** - Organic (HP/LE) + Digital (GE/UI) unified

## Git-Based PKM (Personal Knowledge Management)

### Key Principles

1. **Plain Text Markdown** - Future-proof, portable, vendor-independent
2. **Version Control** - Every change tracked with full history
3. **Open Format** - No lock-in, programmable, analyzable
4. **Distributed Backups** - Local + GitHub + GitLab
5. **Offline-First** - Edit anywhere, sync when online

### Two-Repository Architecture

**OneMind-Codex (Private)**

*   Contains: All personal notes, strategies, finances, health data
*   Access: Private (Zeus only)
*   Version Control: Complete change history
*   Backup: GitHub (private) + GitLab (mirror)

**OneMind-Codex-Live (Public)**

*   Contains: Curated public knowledge
*   Access: Public
*   Purpose: Learning in public
*   Publishing: GitHub (public) + Obsidian Publish

# Numerical Organization System

## The 00-99 Domain Structure

The OneMind-Codex uses a **100-slot numerical system** divided into **4 domains of 25 slots each**:

```yaml
00-24: UI (Sovereign Operations)      - The Brain
25-49: HP (Holistic Performance)      - Self Path
50-74: LE (Legacy Evolution)          - Family Path
75-99: GE (Generational Empire) - Business Path
```

Each domain has 25 numbered folders (00-24, 25-49, etc.), providing room for expansion while maintaining clear organization.

## Naming Convention Pattern

**Format:** `[2-digit-code] [Domain-Name] ([Descriptor])`

### Examples

*   `00 Framework (Doctrine)` - Primary organizational framework
*   `01 Command (Dashboard & Navigation)` - Command center
*   `02 Agents (AI, Memory & Tools)` - AI systems
*   `25 Identity (Self, Purpose & Spirit)` - Personal identity
*   `50 Home (Sanctuary & Property)` - Family property
*   `75 Zeus Delacruz Enterprise (Personal Brand)` - Business entity

## Hierarchical Decimal System

Within each numbered folder, a **decimal system** is used for unlimited depth:

```powershell
00 Framework (Doctrine)/
├── 00.1 Core-Doctrine/
├── 00.2 Architecture/
├── 00.3 Operating-System/
├── 00.4 AI-Agent-Guides/
├── 00.5 Reference/
└── 00.6 Competitors/

02 Agents (AI, Memory & Tools)/
├── 02.1 Index/
├── 02.2 AI-Agent-Frameworks/
├── 02.3 Agents/
│   ├── 02.3.2 00-Mother-AI/
│   ├── 02.3.3 01-HP-Agent/
│   ├── 02.3.4 02-LE-Agent/
│   ├── 02.3.5 03-GE-Agent/
│   └── 02.3.6 04-IT-Agent/
├── 02.4 Architecture/
├── 02.5 Memory/
├── 02.6 Tools/
├── 02.7 Platforms/
├── 02.8 Models/
├── 02.9 Interfaces/
└── 02.10 Skills/
```

### Decimal Notation Levels

*   **00.1** = First subsection (level 3)
*   **00.2** = Second subsection (level 3)
*   **02.3.2** = Folder 02, Subsection 3, Item 2 (level 4)
*   **02.3.3.1** = Even deeper nesting (level 5)

This allows for **unlimited folder depth** while maintaining clear navigation.

# Metadata Schema & YAML Frontmatter

## Universal Metadata Structure

Every markdown file in OneMind-Codex contains **YAML frontmatter** with consistent metadata fields. This enables:

*   AI processing and filtering
*   Automated organization
*   Relationship mapping
*   Version tracking
*   Multi-tool integration

## Standard Frontmatter Fields

| Field | Type | Purpose | Required |
| ---| ---| ---| --- |
| `id` | string | Unique identifier | ✓ |
| `title` | string | Display name | ✓ |
| `type` | enum | Document classification | ✓ |
| `pillar` | string | Which pillar (UI/HP/LE/GE) | Optional |
| `path` | string | Pillar code (alternative) | Optional |
| `domain` | string | Domain range (00-24, etc.) | ✓ |
| `folder` | string | Parent folder name | ✓ |
| `status` | enum | Document status | ✓ |
| `created` | date | Creation date (YYYY-MM-DD) | ✓ |
| `modified` | date | Last modified date | ✓ |
| `owner` | string | Responsible person/agent | ✓ |
| `tags` | array | Categorical tags | ✓ |
| `todoist_project` | string | Linked Todoist project | Optional |
| `ai_summary` | string | AI-generated summary | Optional |

## Field Details

### ID Format

**Pattern:** `[pillar]-[domain]-[timestamp]`

**Examples:**

*   `root-00-20260113225954` - Root-level file
*   `ui-00-20260111053926` - UI domain file
*   `hp-25-20260113225955` - HP domain file
*   `le-50-20260114120000` - LE domain file
*   `ge-75-20260114130000` - GE domain file

### Type Enum Values

Common document types:

| Type | Purpose | Example Files |
| ---| ---| --- |
| `index` | Overview/navigation page | [README.md](http://README.md), [MOC.md](http://MOC.md) |
| `doctrine` | Foundational philosophy | [ONEMIND-CONSTITUTION.md](http://ONEMIND-CONSTITUTION.md) |
| `concept` | Knowledge/idea documentation | [Core-Values.md](http://Core-Values.md) |
| `reference` | Reference material | [Tech-Stack.md](http://Tech-Stack.md) |
| `procedure` | Step-by-step process | SOPs, workflows |
| `experience` | Personal experience/journal | Journal entries |
| `project` | Project documentation | Project plans |
| `area` | Area of responsibility | Domain overviews |

### Status Enum Values

| Status | Meaning | Use Case |
| ---| ---| --- |
| `active` | Currently maintained | Primary working documents |
| `draft` | Work in progress | Incomplete documents |
| `archived` | Completed/historical | Old projects, completed work |
| `hibernated` | Paused but may resume | On-hold projects |

### Tag Prefixes

Tags follow **consistent prefixes** for filtering:

| Prefix | Purpose | Examples |
| ---| ---| --- |
| `type/` | Document type | `type/index`, `type/reference`, `type/doctrine` |
| `status/` | Document status | `status/active`, `status/draft`, `status/archived` |
| `path/` | Pillar reference | `path/hp`, `path/hp/25`, `path/le` |
| `domain/` | Domain code | `domain/so`, `domain/hp`, `domain/ge` |
| `folder/` | Folder reference | `folder/00`, `folder/25`, `folder/75` |

# Entity Model & Universal Schema

## The 8 Core Entity Types

OneMind-Codex organizes all information into **8 universal entity types**. This consistent schema enables:

*   Cross-domain queries
*   Automated workflows
*   AI agent understanding
*   Tool integration
*   Clear mental models

## Entity Type Definitions

### 1\. AREA

**Definition:** Ongoing responsibility with no end date

**Characteristics:**

*   Never completes (always active)
*   Requires continuous attention
*   Contains multiple projects
*   Measured by standards, not completion

**Examples:**

*   "Health & Vitality" (HP domain)
*   "Family Finances" (LE domain)
*   "Product Development" (GE domain)
*   "Infrastructure Maintenance" (UI domain)

**In Codex Structure:**

*   Typically maps to numbered folders (25, 26, 27, etc.)
*   Contains subfolders and files for ongoing work
* * *

### 2\. PROJECT

**Definition:** Time-bound effort with a clear end goal

**Characteristics:**

*   Has a defined completion state
*   Duration: Weeks to months
*   Contains multiple workflows and tasks
*   Measured by progress toward goal

**Examples:**

*   "Repair Credit to 750+" (HP/Finance)
*   "Complete Kitchen Renovation" (LE/Home)
*   "Launch Q1 Content Series" (GE/Brand)
*   "Migrate Database to PostgreSQL" (UI/Infrastructure)

**In Codex Structure:**

*   Documented in markdown files within relevant folders
*   Linked to Todoist for task tracking
*   Metadata: `type: project`, `status: active/completed`
* * *

### 3\. WORKFLOW

**Definition:** Reusable process sequence that can be repeated

**Characteristics:**

*   Standardized steps
*   Repeatable on demand or schedule
*   Can be automated
*   Creates consistent outcomes

**Examples:**

*   "Weekly Review" (UI/Protocols)
*   "Morning Routine" (HP/Life Systems)
*   "Quarterly Financial Review" (LE/Wealth)
*   "Content Publishing Process" (GE/Brand)

**In Codex Structure:**

*   Stored in `/06 Protocols (SOPs)/`
*   Step-by-step documentation
*   May include automation scripts
*   Metadata: `type: procedure`
* * *

### 4\. TASK

**Definition:** Smallest actionable unit of work

**Characteristics:**

*   Single action to complete
*   Duration: Minutes to hours
*   Binary status (done/not done)
*   Part of a project or workflow

**Examples:**

*   "Send dispute letter to Experian"
*   "Schedule dentist appointment"
*   "Update company bio on website"
*   "Deploy hotfix to production"

**In Codex Structure:**

*   Managed in clickup (not in Codex markdown)
*   Linked to Codex via clickup`_list` field
*   Referenced in markdown for context
* * *

### 5\. KNOWLEDGE NODE

**Definition:** Atomic information unit (permanent reference)

**Characteristics:**

*   Single concept or idea
*   Evergreen (doesn't expire)
*   Densely linked to other nodes
*   Source of truth for information

**Examples:**

*   "How to Dispute Credit Report Errors"
*   "Understanding Attachment Theory"
*   "PostgreSQL Connection Pooling"
*   "Content Marketing Frameworks"

**In Codex Structure:**

*   Individual markdown files
*   Rich internal linking (\[\[wikilinks\]\])
*   Metadata: `type: concept` or `type: reference`
*   Lives in appropriate domain folder

**Knowledge Node Schema:**

| Field | Type | Purpose |
| ---| ---| --- |
| `id` | string | Unique identifier |
| `title` | string | Name of the concept |
| `type` | enum | concept / reference / experience |
| `source` | string | Origin/attribution |
| `links` | node\_id\[\] | Related notes and projects |
| `tags` | string\[\] | Categorization |
| `codex_status` | enum | draft / validated / canonical |

* * *

### 6\. AGENT

**Definition:** Actor (human, AI, robot) that performs work

**Characteristics:**

*   Has specific capabilities and constraints
*   Operates within defined scope
*   Can be delegated tasks
*   Has memory and context

**Types:**

*   **Human** - Zeus (owner)
*   **AI** - Mother AI, HP Agent, GE Agent, LE Agent, Grid Agent
*   **Robot** - Physical automation (future)
*   **Hybrid** - Human + AI collaboration

**Examples:**

*   "Mother AI" - Central coordinator agent
*   "HP Path Coach" - Personal development agent
*   "GE Growth Agent" - Business strategy agent
*   "IT Infrastructure Agent" - Tech maintenance agent

**In Codex Structure:**

*   Documented in `/02 Agents (AI, Memory & Tools)/`
*   Each agent has profile file with capabilities
*   Subfolders: `02.3.2 00-Mother-AI/`, etc.
* * *

### 7\. METRIC

**Definition:** Measurement point for tracking progress

**Characteristics:**

*   Quantifiable data point
*   Tracked over time
*   Feeds intelligence scores (PI, LI, WI)
*   Drives decision-making

**Examples:**

**HP Metrics (Performance Intelligence):**

*   Sleep Score (7-9 hours)
*   Body Weight / Body Fat %
*   Meditation Streak
*   Reading Hours/Week
*   Net Worth

**LE Metrics (Legacy Intelligence):**

*   Date Nights/Month
*   Quality Time with Kids (hours/week)
*   Family Emergency Fund Balance
*   Estate Plan Completion %

**GE Metrics (Wealth Intelligence):**

*   Monthly Recurring Revenue (MRR)
*   Content Publishing Streak
*   Email List Growth Rate
*   Profit Margin %

**In Codex Structure:**

*   Tracked in spreadsheets or databases
*   Visualized in dashboards
*   Referenced in markdown files
*   Feeds weekly intelligence score calculation
* * *

### 8\. INTERFACE

**Definition:** Surface where interaction happens

**Characteristics:**

*   Point of contact between human and system
*   Can be visual, voice, or API
*   Optimized for specific use case
*   Tool-specific implementation

**Types:**

*   **Desktop Apps** - Obsidian, VS Code
*   **Mobile Apps** - Todoist, notes
*   **Dashboards** - Analytics, metrics
*   **Chat** - AI conversations
*   **Voice** - Future voice interface
*   **API** - Programmatic access

**Examples:**

*   Obsidian - Primary knowledge interface
*   Todoist - Task management interface
*   Chat with Mother AI - Conversational interface
*   Command Dashboard - Visual metrics interface

**In Codex Structure:**

*   Documented in `/02.9 Interfaces/`
*   Configuration and setup guides
*   Tool-specific workflows
* * *

## Entity Relationships

### Hierarchy

```scss
AREA
  ├── PROJECT (time-bound effort within area)
  │   ├── WORKFLOW (reusable process)
  │   │   └── TASK (smallest action)
  │   └── TASK (one-off action)
  └── KNOWLEDGE NODE (reference information)

AGENT (performs tasks, creates knowledge)
  ├── Has access to KNOWLEDGE NODES
  ├── Completes TASKS
  └── Monitors METRICS

METRIC (measures progress)
  ├── Tracks AREA health
  ├── Tracks PROJECT progress
  └── Feeds intelligence scores

INTERFACE (interaction surface)
  └── Displays entities and enables actions
```

# Intelligence Scores & Metrics

## The Three Intelligence Scores

OneMind-Codex measures life optimization through **three intelligence scores** (0-100 scale):

```
PI (Performance Intelligence) - How optimized is ME?
LI (Legacy Intelligence)       - How protected is US?
WI (Wealth Intelligence)       - How much VALUE am I creating?

Unified Score = (PI + LI + WI) / 3
```

Each score is calculated from **domain-specific metrics** tracked weekly.
* * *

## PI: Performance Intelligence (HP Domain)

**Question:** "Does this improve ME?"

**Measures:** Personal optimization, health, skills, relationships

### HP Domain Breakdown (25-49)

## Unified Score Calculation

### Weekly Unified Score

```
Unified Score = (PI + LI + WI) / 3

Example:
PI = 79.3
LI = 83.5
WI = 77.8

Unified Score = (79.3 + 83.5 + 77.8) / 3 = 80.2
```

## Common Pitfalls & Solutions

### Pitfall 1: Over-Structuring

**Problem:** Spending more time organizing than doing

**Solution:**

*   Use the "2-minute rule" - if organizing takes longer than doing, just do it
*   Focus on active projects, don't perfect old notes
*   Remember: "Good enough" is better than "perfect someday"

### Pitfall 2: Tool Hopping

**Problem:** Constantly switching tools, never settling in

**Solution:**

*   Commit to one tool stack for minimum 90 days
*   Focus on processes, not tools
*   Remember: The system is tool-agnostic by design

### Pitfall 3: Metric Overload

**Problem:** Tracking too many metrics, analysis paralysis

**Solution:**

*   Start with 3-5 metrics per domain
*   Focus on leading indicators (inputs) not lagging (outputs)
*   Remove metrics that don't drive action

### Pitfall 4: Neglecting Maintenance

**Problem:** System becomes outdated, links break, content stales

**Solution:**

*   Schedule recurring maintenance tasks
*   Use weekly reviews to catch issues early
*   Archive aggressively - when in doubt, archive

### Pitfall 5: Solo Operation

**Problem:** No accountability, easy to skip reviews

**Solution:**

*   Find accountability partner
*   Share weekly unified score
*   Join community of practice (if public version)
*   Use AI agents as "check-in buddies"
