## Specific failure and correction

The failing view includes this valid PostgreSQL FROM expression:

```sql
JOIN LATERAL COALESCE(constraint_tstzrange(pg_get_expr(c.relpartbound, c.oid)), inf_range) as partition_dtrange ON TRUE
```

The pinned AGE `is_func_cypher` path treats the special PostgreSQL `CoalesceExpr`
as a `FuncExpr`. This matches [upstream AGE issue 2256 and fix 2259](https://github.com/apache/age/pull/2259).
The pinned source lacks that fix. A backtrace from this local process was not
collected; the controlled A/B result, exact failing statement and matching upstream
source establish the scoped compatibility problem without claiming a new AGE fix.

`migrate-compat.py` replaces only that FROM expression with its equivalent one-row
lateral SELECT:

```sql
JOIN LATERAL (SELECT COALESCE(constraint_tstzrange(pg_get_expr(c.relpartbound, c.oid)), inf_range) AS partition_dtrange) AS partition_dtrange ON TRUE
```

The transformation preserves correlation, null fallback, the original pypgstac CLI,
full-file transaction, role operations and migration/version checks. It skips no
statement. It checks the client version, exact bootstrap SQL SHA-256
`781d5d2936e599d01c239ac8e65f39798e48ba5cd36b7009d4cdc031e9a9bf8a`
and exactly one target occurrence. Changed SQL, a missing/ambiguous clause and
unreviewed upgrade files are rejected. Production and diagnostic ConfigMaps embed
exactly the same source, enforced by tests.

This corrects STAC's use of the expression; the globally loaded AGE library still
has the underlying bug for other callers. A native-library repair belongs in a
separate reviewed change with graph and shared-database tests. Do not remove global
AGE preload or alter production role privileges to make this migration pass.
