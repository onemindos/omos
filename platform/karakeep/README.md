# Karakeep — native Kubernetes preparation

Prepared source only. Argo Application `platform-karakeep` is **manual**, and all three Deployments have **replicas: 0**. No application process, SQLite migration, account or search index starts from this source state. The private address is **https://karakeep.tail717ba0.ts.net**; it is a proposed route until manual deployment and authenticated browser acceptance pass. No public Ingress, LoadBalancer, NodePort or Funnel is configured.

## Native source and dependencies

Adapted from the official [Kubernetes/Kustomize installation](https://docs.karakeep.app/installation/kubernetes/) and [v0.34.1 native manifests](https://github.com/karakeep-app/karakeep/tree/ebd122bb45b38d9dd45f7c6db55b5587bf6b1265/kubernetes), not a Compose translation or community Helm chart. `upstream.lock.json` records exact upstream commit, source checksums and registry-verified image index digests. Updates must review those native resources and release notes before replacing the pins.

| Piece | Pin | Role / persistent state |
| --- | --- | --- |
| `web` | Karakeep 0.34.1 | Official combined web/worker image; SQLite and assets at `/data` on `data-pvc` (20Gi) |
| `chrome` | Karakeep Chrome 154.0.8037.57-r1 | Official browser image; ephemeral `/tmp`, no PVC |
| `meilisearch` | Meilisearch v1.41.0 (upstream native pin) | Supported full-text search; `meilisearch-pvc` (5Gi) |

The metadata preflight found no existing Karakeep, Hoarder, Meilisearch or shared browser workload. Existing shared OpenSearch cannot replace Meilisearch through the supported Karakeep setting. Karakeep's database is SQLite; no shared CNPG database or new PostgreSQL server is introduced. Search and browser dependencies are dedicated because they are the official supported native layout. OpenAI-compatible AI tagging and embeddings are optional; no inference credential, model server or gateway route is configured. Automatic tagging/summaries, embeddings, semantic search and OCR start disabled. Enabling them is a separate reviewed configuration/integration, not app acceptance.

The official native service defaults to LoadBalancer; here it is ClusterIP behind the Tailscale operator. Plaintext Kustomize secretGenerator/.secrets is replaced by strict SealedSecret `karakeep/karakeep-secrets`, keys `NEXTAUTH_SECRET` and `MEILI_MASTER_KEY`. These are new random app-only values generated and sealed in memory; no existing credential was read or rotated. Keep them with the recovery material. The upstream sample's legacy `NEXT_PUBLIC_SECRET` is absent from v0.34.1 shared config and is not generated. No user/provider/SMTP/OIDC credential is invented.

## Initial budgets and isolation

At activation, requests total **600m CPU / 1792Mi memory**, limits **4 CPU / 4608Mi memory**, plus the Tailscale proxy and storage/backup overhead. These are initial estimates, not measured usage. All replicas currently zero. Recheck capacity after the ongoing shared-database recovery and other app rollouts; keep a single web writer and Recreate strategy for both RWO stateful workloads.

Startup/readiness/liveness probes use upstream `/api/health`, Chrome `/json/version` and Meilisearch `/health`. The web health route proves the HTTP process responds; it does not certify search, crawling, workers, authentication or recovery. Namespace PSA is restricted, Kubernetes API tokens are disabled, and pods are non-root with dropped capabilities and RuntimeDefault seccomp. The web image's s6 init needs writable container runtime/cache paths, so only Chrome/Meilisearch have read-only root filesystems. These settings follow the upstream baked node-owned `/run` and browser UID65534, but have not been run against this live cluster; inspect bounded startup failures before changing them.

Default-deny ingress/egress allows DNS; only the named Karakeep Tailscale ingress proxy can reach web3000; only web can reach chrome9222 and meilisearch7700. Web and Chrome can fetch public IPv4 HTTP/HTTPS, excluding private, tailnet, loopback, link-local/metadata and reserved ranges. Meilisearch has no public egress. There is no route to CNPG, model gateways, internal services or private bookmark targets. Changing that is an intentional scope expansion. [Upstream security guidance](https://docs.karakeep.app/administration/security-considerations/) still treats crawler input as trusted-user access: the browser runs upstream `--no-sandbox`, and website crawling uses this server's public IP. Do not treat the basic SSRF checks as complete isolation.

## Manual activation order

1. Review exact-main Argo diff and current cluster capacity/recovery. Preserve the manual Application and scale-zero state while preparing storage/identity/recovery. Argo app-of-apps may create this Application after merge, but it must not sync its resources automatically.
2. Manually reconcile namespace, PVCs, sealed app values, generated config, policies, Services and Ingress through `platform-karakeep`. Confirm SealedSecret Synced and only expected key names without printing values. Record PVC UIDs/PVs and keep their Prune/Delete/Force/Replace guards. A private HTTPS route with zero endpoints is expected at this stage and is not a working-link claim.
3. Complete the [backup/recovery preparation](BACKUP.md), approved first-owner enrollment plan and initial resource review before meaningful data is stored. Signups are disabled and password login remains enabled. Either provision approved OIDC separately, or temporarily permit only the intended owner's bootstrap under a restricted tailnet access policy, then disable signups again before expanding access. Do not enable open enrollment by default or weaken existing Authentik email verification. OIDC needs reviewed `OAUTH_WELLKNOWN_URL`, `OAUTH_CLIENT_ID` and sealed `OAUTH_CLIENT_SECRET`; callback is `https://karakeep.tail717ba0.ts.net/api/auth/callback/custom`.
4. In a separate reviewed Git activation, set `chrome` and `meilisearch` replicas to one; reconcile them first and observe readiness. Then set `web` to one and reconcile. **Starting web automatically runs SQLite migrations inside the official image before web/workers**, as its native Dockerfile/s6 scripts specify. There is no supported promise to preview or reverse those migrations; this is the explicit first-start approval gate. No manual `kubectl scale`, init SQL or direct workload apply.
5. Verify the live tailnet route's TLS, login/session/CSRF behavior, closed registration and account access. Store a harmless bookmark and attachment, exercise full-text search and a permitted public-page crawl/screenshot; confirm private/metadata targets remain blocked. Confirm a unique scoped API key and official API/CLI or MCP access for an agent in a separate authenticated enrollment; do not reuse app secrets as user API keys. No agent key or messages are created by this source.
6. Confirm restart/persistence and an isolated restore with bookmark, attachment and search checks before normal usage/import. Verify Android/iOS/extension compatibility, offline download/reading and later resync separately; no offline/home-autonomy claim follows from a tailnet URL. The official v0.34 release adds native offline capabilities, but they were not exercised here.

## Backup, upgrade and rollback gates

See [BACKUP.md](BACKUP.md). Keep namespace/PVCs/sealed values on rollback. Before upgrades, take and verify a recoverable full data backup; read release/migration compatibility and Meilisearch dump/reindex requirements. Reverting an image commit does not reverse database/index migrations. Source-only failure can revert the Argo/source change while no app has started; after first start stop web via reviewed Git and restore into an isolated new claim first. Never delete/recreate claims, reset SQLite or rotate auth/search keys just to clear readiness.

Local verification: `kubectl kustomize platform/karakeep`, strict kubeconform, changed-YAML/manifest gates and `python3 -m unittest discover -s scripts/tests -p 'test_gitops_karakeep.py'`. No image execution, live deployment, browser acceptance, account enrollment, backup upload/restore or inference was performed during preparation.
