# Gatus: live health for apps outside Kubernetes

Prepared 2026-11-05 (flagship F7), **not deployed**. The Argo Application `platform-gatus` has manual sync:
nothing runs until Zeus syncs it. Gatus runs HTTP(S) checks and certificate-expiry checks and shows them in
its own UI, in Prometheus and on the portal app page.

## What is here

| File | Purpose |
| --- | --- |
| `endpoints.yaml` | **Generated** from the catalog. Do not edit. |
| `test-endpoints.yaml` | One deliberate failure, `test-deliberate-failure`. |
| `config.yaml` | Gatus settings: metrics on, in-memory storage, UI title. |
| `deployment.yaml` | Pod (hardened), Service and the Tailscale Ingress `status`. |
| `network.yaml` | Ingress only from the Tailscale proxy, Prometheus and the portal. |
| `servicemonitor.yaml`, `prometheusrule.yaml` | Metrics scrape and the alerts. |

Gatus reads every file in `/config` and merges the endpoint lists. The ConfigMap is generated by Kustomize with a
content hash, so a changed check restarts the pod.

## Add or change a check

Checks come from catalog annotations, never from this directory:

1. In `services/onemind-portal/catalog/apps.yaml`, give the Component `onemind.io/health-check: <name>` (the Gatus
   endpoint name, lower case and hyphens) and `onemind.io/health-url: <url>`. Contract:
   [docs/catalog/app-contract.md](../../docs/catalog/app-contract.md).
2. `node services/onemind-portal/scripts/generate-gatus-endpoints.cjs`
3. `cp services/onemind-portal/catalog/apps.yaml platform/backstage/catalog/apps.yaml`
4. Commit all three. CI (`test-gatus-endpoints.cjs`) fails when `endpoints.yaml` is stale.

Rules the generator applies: `[STATUS] < 400` for every endpoint; plain `http://` (in-cluster) endpoints are checked
every minute with `[RESPONSE_TIME] < 3000`; `https://` endpoints every five minutes with
`[CERTIFICATE_EXPIRATION] > 336h` (14 days). The group is the app's hosting kind.

Reachability: Gatus runs in the cluster, so use in-cluster Service URLs for cluster apps and public HTTPS URLs for SaaS.
`*.tail717ba0.ts.net` hosts are not reachable from the pod without the Tailscale egress proxy; do not use them. A
Service in a namespace with a default-deny NetworkPolicy (for example `argocd`, `nats`, `forgejo`) also needs a
policy that admits the `gatus` namespace before it can be checked.

Gmail and Monarch are named in the F7 work order but have no catalog Component yet, so they have no check. Add the
Component first, then the two annotations.

## Remove the deliberate failure

`test-deliberate-failure` points at a Service that does not exist. It is red on purpose, shows red on the Gatus page,
and fires `GatusEndpointDown` after five minutes. Once you have seen the alert, delete `test-endpoints.yaml`, delete
its line under `configMapGenerator` in `kustomization.yaml`, commit, and sync `platform-gatus`.

## Storage and backup

In-memory storage, no PVC, nothing to back up. **History resets whenever the pod restarts** and the portal then shows
checks as "Not checked yet" until the first interval passes. Prometheus keeps the long history
(`gatus_results_endpoint_success`, `gatus_results_duration_seconds`, `gatus_results_certificate_expiration_seconds`).

## Resources

Requests 10m CPU and 48Mi memory, limits 200m and 128Mi. Measured 16 MiB with two endpoints. The ecosystem node
(`onemind-ecosystem-cpu`) was at 81% CPU and 84% memory requested on 2026-11-05, so the request is deliberately small;
the pod prefers that pool and can move if it is full.

## Alerts

`GatusEndpointDown` (a check failing for 5 minutes), `GatusCertificateExpiring` (under 14 days) and `GatusDown`
(Prometheus cannot scrape Gatus). All are severity `warning` and use the default Alertmanager route. There is no
Telegram receiver (on hold).

## Before the first sync

1. Review and merge the PR that adds this directory.
2. Sync `platform-gatus` in Argo CD. It creates the namespace, the pod, the Tailscale Ingress `status` and the rules.
3. Open `https://status.tail717ba0.ts.net`: the cluster and SaaS checks should be green after one interval and
   `test-deliberate-failure` red.
4. The portal status card reads Gatus through the `/api/proxy/gatus` route. That route ships in the portal config
   (`platform/backstage/app-config.cluster.yaml`) and needs the portal to restart after the PR merges.
