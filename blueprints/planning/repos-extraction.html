2 The four world repos — pattern, extraction, verdict

🛰️ Crucix DELETE AFTER SAVE

"Intelligence terminal — 27 sources, zero cloud." A clean folder of self-contained fetch adapters, one file per source.

Pattern One adapter = one source. Each .mjs is a pure function: hit an API → return normalized JSON. No framework, no state. This is the ideal connector shape — exactly what omos-feed-* wraps.
What we took (29 adapters w/ live endpoints):
  • Air: adsb, opensky · Sea: ships (aisstream)
  • Space/RF: space (Celestrak), kiwisdr
  • Hazard: firms, noaa, safecast, epa, who
  • Conflict: acled, gdelt, reliefweb
  • Cyber: cisa-kev, cloudflare-radar
  • Finance/sanctions: ofac, opensanctions, treasury, fred, yfinance, bls, eia, comtrade, usaspending, gscpi, patents
  • Social: telegram, reddit, bluesky
  • + briefing prompts (BRIEFING_PROMPT.md)

Upgrade to omos: these become the guts of omos-feed-world / omos-feed-intel, but instead of returning to a web UI, they publish to the bus → reach ATAK, atoc, agents, ClickHouse all at once.

Safe to delete once apis/sources/ + BRIEFING_PROMPT.md are copied into omos-core. That folder is the repo's whole value.

🌍 worldmonitor DELETE AFTER SAVE

AI geopolitical situational-awareness dashboard. The richest repo — a curated intelligence catalog, not just code.

Pattern Curated registries + tiered resolution. Sources ranked by trust tier; feeds resolved/deduped/failure-handled; the world pre-labeled into static geo tables (bases, cables, chokepoints). The idea: the value is the curation, not the fetcher.
What we took:
  • 487 curated feeds · 279 tier-ranked sources (Reuters→Janes→CISA)
  • 56 map layer definitions (visibility rules, deck.gl gating)
  • Live adapters: RSS, GDELT-intel, Aviation, Maritime/AIS, Conflict (ACLED/UCDP/HAPI)
  • Geo gold (map overlays): military bases 210, APT groups 159, AI datacenters 313, airports 111, ports 76, pipelines 40+, trade routes 21, bypass corridors 26, undersea cables, chokepoints, hotspots
  • Mapping: MapLibre + deck.gl + PMTiles/Protomaps basemap config → your sovereign-Earth blueprint (see §4)
Safe to delete after copying src/config/* (feeds, registries, basemap) + src/services/* adapters into omos-core. This repo hands you the entire WORLD + INTEL source catalog and the map overlays in one shot.

⬡ Osiris DELETE AFTER SAVE

OSINT recon workspace (Next.js). 34 API routes, each a domain intelligence layer. The deep-recon specialist.

Pattern Route = capability, with composition + guards. Routes chain each other (region-dossier = reverse-geocode → Wikipedia → Wikidata; scm-suppliers = fires + gdelt). Hardened with ssrf-guard, safeFetch, stealthFetch, rate limits. The idea: composable enrichment + safe outbound fetching.
What we took (routes = future omos capabilities):
  • Recon that others lack: osint (DNS/BGP/WHOIS/IP), malware, cctv (traffic cams), scanner, radar, sentinel, region-dossier, entity/expand
  • Overlap (confirm coverage): flights, maritime, satellites, weather, fires, air-quality, earthquakes, space-weather, conflicts, frontlines, country-risk, infrastructure, cyber-threats, markets, crypto, news
  • ai/briefing + ai/analyze → the analyst pattern (a Hermes job)
  • Security patterns for any omos connector that fetches the public internet
  • proxy-tiles → map tile proxying pattern
Safe to delete after copying the recon-specialty routes (osint/, cctv/, region-dossier, malware, scanner) + the ssrf-guard/safeFetch helpers. The overlapping routes are already covered by Crucix adapters — take Osiris for its unique recon depth.

🌐 worldwideview KEEP (3D ref)

Plugin-driven CesiumJS 3D globe — "cinematic geospatial layers." Your future 3D / mission-viz north star.

Pattern Plugin globe. A globe core + a plugin interface: each plugin registers, fetches its own data, and renders its own layer. Add a capability = drop in a plugin. The idea: the map is a platform, layers are plugins.
What we took:
  • The plugin-layer architecture → model for future omos-globe (3D missions, flyovers)
  • Cesium entity/layer rendering patterns (world-space, not 2D dots)
  • Confirms: 2D (MapLibre) now, 3D (Cesium) later — same bus streams feed both
Keep one copy as the 3D reference. Nothing to run now — it sits on the exact same WORLD/INTEL streams when 3D becomes a priority.

4 The mapping structure — what we duplicate

You said "I want my own maps" and "consider duplicating their mapping structure." Here it is — and the good news: worldmonitor already coded the sovereign path.

🗺️ 2D tactical map — duplicate now

Source: worldmonitor basemap.ts already uses MapLibre + PMTiles/Protomaps alongside Carto/OpenFreeMap styles.

What that means: PMTiles = one file = the entire planet's base map, self-hosted, offline, no Google/Mapbox. MapLibre reads it natively. This is your "download the Earth" — and it's already proven in your own repo.

Duplicate as omos-maps: serve one planet .pmtiles file → consumed by atoc (MapLibre), WebTAK, and ATAK (offline packs). GeoServer stays for tactical overlays.

Copy: src/config/basemap.ts, basemap-styles.ts, map-layer-definitions.ts (56 layers), cii-colors.ts (symbology).

🌐 3D globe — later, same data

Source: worldwideview's CesiumJS plugin globe.

What that means: world-space 3D (exact position, flyovers, mission rehearsal) — the "cinematic" layer. Its plugin model = add a globe layer by dropping in a plugin.

Duplicate later as omos-globe: subscribes to the same WORLD/INTEL/GEO streams the 2D map uses. Zero new data work — it's a second renderer on the same bus.

Keep worldwideview as the reference. Build when 3D/mission-viz becomes a priority, not before.

The overlay layers (bases, cables, chokepoints, ports…) are renderer-agnostic GeoJSON — they light up on the 2D map now and the 3D globe later, identically. One source of truth, many views. That's the sophisticated structure you're after.
