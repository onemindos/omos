The OneMind Connector — one shape for every feed

① FETCH

Pull from the source API (the logic Crucix/WM already wrote). Retries + backoff + rate-limit respect built in.

② NORMALIZE

Map to the common entity schema (lat/lon/type/time/confidence).

③ PUBLISH

nats.publish(subject, data) to its assigned subject. Nkey-scoped: can ONLY publish its own subject.

④ EXPOSE

/health + Prometheus /metrics (last-success, rate, errors). Structured logs.

Each connector = one container image built from one template. Config (interval, region, subject, secret ref) comes from a manifest — not baked in. Swap the fetch block, keep everything else.

Where they run — Cloud (K8s) vs Edge (NEX)

☁ Cloud connectors → DOKS / K8s

  • All internet-API feeds: Crucix 29, WM layers, Osiris
  • Need stable egress, secrets, always-on
  • Polling feeds → CronJob · streaming feeds → Deployment
  • Auto-restart, resource limits, network policies
  • Publish to the cloud NATS cluster

⚡ Edge connectors → NEX

  • Physical sensors born at the edge: MAVLink drones, cameras, RF/SDR, home-assistant
  • Run near the hardware (low latency, offline-tolerant)
  • Publish to the leaf NATS → syncs to cloud
  • NEX = your edge function runtime; this is exactly its job

Control · Stability · Safety — the governance layer

🎛 CONTROL

GitOps. Every connector = a manifest in omos-infra. On/off, interval, subject via git commit. om-control-plane = runtime view of what's live.

🛡 STABILITY

K8s self-heals crashed pods. Each connector isolated in its own pod — one crash never touches ORP or others. JetStream buffers through restarts. Resource limits.

🔒 SAFETY

Secrets via 1Password → K8s Secrets (never in code). NATS nkeys: a connector can ONLY publish its subject. TLS everywhere. ORP Ed25519 signed audit log. Network policies.

📊 OBSERVABILITY

Prometheus scrapes every connector + NATS + ORP. Grafana "feed health" board: is every source publishing? rate? last success? Alert on silent feed.
